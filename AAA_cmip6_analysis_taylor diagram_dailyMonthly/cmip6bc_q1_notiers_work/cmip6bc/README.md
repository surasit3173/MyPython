# cmip6bc

Split-sample bias correction and independent temporal validation of CMIP6
daily rainfall.

การปรับแก้อคติข้อมูลฝนรายวันจากแบบจำลอง CMIP6 ด้วยการแบ่งช่วงข้อมูล
และตรวจสอบความถูกต้องข้ามช่วงเวลาแบบอิสระ

---

## 1. โปรแกรมนี้ทำอะไร

    fit(calibration) → freeze → apply(validation)

ประมาณฟังก์ชันการแปลงจากช่วงปรับแก้เท่านั้น ตรึงค่าพารามิเตอร์
แล้วนำไปใช้กับช่วงตรวจสอบโดยไม่ประมาณค่าใหม่

**ข้อมูลตรวจวัดในช่วงตรวจสอบไม่ถูกใช้ในการประมาณค่าใด ๆ**
และข้อกำหนดนี้พิสูจน์ได้ด้วยการทดลอง ไม่ใช่การกล่าวอ้าง — ดูหัวข้อ 6

ผลลัพธ์ที่ได้: ชุดข้อมูลที่ปรับแก้แล้ว · ตารางประเมินผล ·
รูปประกอบระดับตีพิมพ์ · บันทึกที่มาของข้อมูลทุกขั้นตอน

---

## 2. ติดตั้ง

ต้องใช้ Python 3.9 ขึ้นไป

    pip install -r requirements.txt

ตรวจสอบว่าติดตั้งครบด้วย

    python run_all.py --config config.yaml

หากขาดแพ็กเกจใด โปรแกรมจะแจ้งชื่อและคำสั่งติดตั้งก่อนเริ่มทำงาน

**ฟอนต์ของรูป** โปรแกรมจะเลือก Cordia New เป็นอันดับแรกเสมอ
บนเครื่องที่ไม่มี Cordia New จะตกไปใช้ Garuda ซึ่งเป็นฟอนต์คู่เทียบ
metric-compatible แล้วพิมพ์แจ้งให้ทราบทุกครั้ง
เปลี่ยนลำดับได้ที่ `figures.font_family` ใน `config.yaml`

## 3. เตรียมข้อมูล

วางไฟล์ทั้งหมดไว้ใน `./data`

    data/
    ├── Observed_Rain_daily_198101_201412_<REGION>.csv
    ├── pr_day_ACCESS-ESM1-5_historical_r1i1p1f1_gn_19810101-20141231_<REGION>.csv
    ├── pr_day_CESM2_historical_r11i1p1f1_gn_...csv
    ├── ...
    └── stations.csv

**รูปแบบไฟล์ฝนรายวัน** คอลัมน์เวลาสามคอลัมน์ ตามด้วยรหัสสถานีคอลัมน์ละสถานี

    YEAR,MONTH,DAY,500001,500002,500003,...
    1981,1,1,0.0,0.0,2.5,...

**รูปแบบ `stations.csv`** เป็นทะเบียนระดับประเทศได้ โปรแกรมจะเลือกเฉพาะ
สถานีที่ปรากฏในไฟล์ตรวจวัด

    CODE,latitude,longitude,elev
    500001,12.37,99.95,9.13

โปรแกรมจัดการให้อัตโนมัติ

- ตรวจหน่วย ถ้าเป็น kg m⁻² s⁻¹ จะคูณ 86400 ให้เอง
- ตรวจปฏิทิน แยกแยะ standard, 365_day, 360_day และจับคู่วันที่ตามจริง
  โดยไม่บังคับให้ทุกแบบจำลองมีจำนวนวันเท่ากัน
- แทนค่าที่ประกาศเป็น NoData ก่อน แล้วจึงปรับค่าติดลบเป็นศูนย์
  เฉพาะที่อยู่ในค่าความคลาดเคลื่อนที่กำหนด ค่าที่ลึกกว่านั้นถูกทำเป็น NaN
  พร้อมรายงาน — **ลำดับนี้สำคัญ** ถ้าปรับค่าติดลบก่อน รหัส −99 จะกลายเป็น 0

## 4. วิธีรัน

### รันทั้งหมดในคำสั่งเดียว

    python run_all.py --config config.yaml

ใช้เวลาประมาณหนึ่งนาทีสำหรับ 12 สถานี × 5 แบบจำลอง × 34 ปี

### รันทีละขั้นตอน

    python run.py          --config config.yaml --stage io   # หยุดหลัง QC gate 1
    python run.py          --config config.yaml              # ผ่าน QC gate 2
    python test_leakage.py --config config.yaml              # พิสูจน์ว่าไม่มีการรั่วไหล
    python evaluate.py     --config config.yaml              # ประเมินผล + sensitivity
    python figures.py      --config config.yaml              # สร้างรูป

### เปรียบเทียบ Parametric และ Non-parametric QDM

สคริปต์นี้เป็นงานวิเคราะห์เสริมสำหรับบทความที่ต้องการเปรียบเทียบ
QDM แบบพาราเมตริกและนอนพาราเมตริก โดย fit เฉพาะช่วง calibration
แล้วตรวจสอบช่วง validation แบบอิสระ

    python qdm_parametric_nonparametric.py --config config.yaml

ผลลัพธ์จะถูกเขียนไปที่ `../../qdm_p_np_publication_out` เป็นค่าเริ่มต้น
เพื่อไม่ทับผลลัพธ์เดิมใน `out/`

    qdm_p_np_publication_out/
    ├── corrected/                         # 5 models × 4 QDM methods
    ├── QDM_parametric_nonparametric_results.xlsx
    ├── fit_diagnostics.csv                # AIC, K-S, distribution ที่ถูกเลือก
    ├── station_metrics.csv
    ├── summary.csv
    └── figures/                           # PNG 600 dpi + PDF vector

เมื่อแก้เฉพาะรูปและไม่ต้องการ fit distribution ใหม่ ให้ใช้

    python qdm_parametric_nonparametric.py --config config.yaml --figures-only

แนะนำให้รัน `--stage io` ก่อนเสมอเมื่อใช้ข้อมูลชุดใหม่ เพื่อดูผลการคัดกรอง
คุณภาพสถานีและปฏิทินก่อนเดินหน้าต่อ

## 5. ย้ายไปใช้กับจังหวัดหรือลุ่มน้ำอื่น

แก้ `config.yaml` ไฟล์เดียว ไม่ต้องแตะโค้ด ใช้ `config_template.yaml`
เป็นจุดตั้งต้น บรรทัดที่ต้องแก้มีเครื่องหมาย `<<< แก้` กำกับไว้

สิ่งที่ควรทบทวนเมื่อเปลี่ยนพื้นที่

| รายการ | เหตุผล |
|---|---|
| `region.tag` | ใช้กรองไฟล์เมื่อโฟลเดอร์เดียวมีหลายพื้นที่ |
| `periods` | แนะนำแบ่งราว 60/40 และให้ช่วงตรวจสอบยาวอย่างน้อย 10 ปี |
| `station_screening.physical_plausibility` | เกณฑ์ปัจจุบันตั้งจากภูมิอากาศมรสุมเขตร้อน พื้นที่แห้งแล้งหรือเขตอบอุ่นต้องปรับใหม่ |
| `data.nodata_values` | เพิ่มรหัสค่าสูญหายที่หน่วยงานเจ้าของข้อมูลใช้ |
| `discovery.*_regex` | แก้เมื่อรูปแบบชื่อไฟล์ต่างจากมาตรฐาน CMIP6 |

**เกณฑ์คัดกรองต้องประกาศก่อนดูผล** หากปรับเกณฑ์หลังเห็นผลลัพธ์แล้ว
จะกลายเป็นการเลือกรายงาน ซึ่งเป็นข้อบกพร่องแบบเดียวกับ data leakage
ในรูปแบบใหม่

สิ่งที่โปรแกรมอนุมานจากข้อมูลเอง ไม่ต้องกำหนด

- รายชื่อสถานี จากหัวคอลัมน์ของไฟล์ตรวจวัด ตัดกับทุกไฟล์แบบจำลอง
- รายชื่อแบบจำลอง จากชื่อไฟล์ผ่าน regex
- ฤดูฝน จากวัฏจักรภูมิอากาศรายวันที่เกลี่ยด้วยหน้าต่าง 30 วัน
  แล้วหาช่วงต่อเนื่องที่ยาวที่สุดซึ่งสูงกว่าค่าเฉลี่ยรายปี
- ปฏิทินและหน่วยของแต่ละแบบจำลอง

## 7. การจำแนกระดับคุณภาพสถานี

ระดับคุณภาพเป็น **การจำแนกเชิงวิเคราะห์** ไม่ใช่ตัวกรองข้อมูล
ทุกสถานีอยู่ในการวิเคราะห์ทุกขั้นตอน

    A  ผ่านทั้งสามกลุ่มเกณฑ์
    B  ผ่านเกณฑ์ความเป็นไปได้เชิงกายภาพเท่านั้น
    C  ไม่ผ่านเกณฑ์ความเป็นไปได้เชิงกายภาพ

    ผลหลัก      = ทุกสถานี
    ความคงทน    = Tier A+B

เกณฑ์แยกตามสิ่งที่วัดจริง ไม่ปนกัน

    physical_plausibility  ค่าเช่นนี้เกิดขึ้นได้จริงในธรรมชาติหรือไม่
    temporal_structure     ลายเซ็นทางสถิติของการเกลี่ยหรือเติมค่า
    homogeneity            หลักฐานทางสถิติของการเปลี่ยนแปลงเชิงระบบ

## 8. สิ่งที่บังคับไว้ในโค้ด ไม่ใช่เพียงข้อความในบทความ

- **ไม่มีการสร้างค่าเฉลี่ยพหุแบบจำลองรายวัน** `build_mme_monthly`
  รวมเป็นรายเดือนก่อนเสมอ การเฉลี่ยรายวันข้ามแบบจำลองที่เหตุการณ์ฝน
  ไม่ตรงเฟสกันจะทำให้ความถี่วันฝนตกสูงเกินจริง ความแปรปรวนลดลง
  และเหตุการณ์สุดขั้วถูกลดทอน
- **ความถี่วันฝนตกช่วงปรับแก้ถูกติดสถานะ construction-dependent**
  ใน `metrics.METRIC_GROUP` เพราะการปรับความถี่บังคับให้ค่านี้ตรงกัน
  โดยการออกแบบ จึงไม่ใช่หลักฐานความสามารถ
- **BH-FDR ที่ถูกต้อง** `metrics.benjamini_hochberg` ใช้ step-up
  ที่ย้อนกลับไปปฏิเสธทุกสมมติฐานที่อันดับต่ำกว่าอันดับสูงสุดที่ผ่านเกณฑ์
  และคืนค่า q-value เป็นตัวเลข การตรวจทีละสมมติฐานแบบตรงไปตรงมา
  จะปฏิเสธน้อยเกินจริง
- **ไม่ใช้เกณฑ์ Moriasi et al. (2007)** กับฝนรายวันจากแบบจำลอง
  เพราะพัฒนามาสำหรับน้ำท่ารายเดือนที่จับคู่เหตุการณ์ได้

## 9. การอนุมานทางสถิติ

การสุ่มซ้ำแบบบล็อกโดยใช้ปีปฏิทินเป็นหน่วยบล็อก จำนวน 2,000 ครั้ง
บนช่วงตรวจสอบ พร้อมควบคุมอัตราการค้นพบเท็จตามวิธี Benjamini-Hochberg

เหตุผลที่ไม่ทดสอบข้ามสถานี: สถานีจำนวนมากตกอยู่ในกริดเซลล์เดียวกัน
ของแบบจำลองและได้รับข้อมูลนำเข้าที่เหมือนกันทุกประการ จึงไม่เป็นอิสระ
ต่อกัน `qc_spatial_information.csv` รายงานจำนวนค่าที่แตกต่างกันต่อวัน
ข้ามสถานี ซึ่งเป็นหลักฐานตรงของข้อจำกัดนี้

ข้อจำกัดที่ต้องระบุในบทความ: ช่วงตรวจสอบมีเพียง 14 บล็อกรายปี
ช่วงความเชื่อมั่นจากการสุ่มซ้ำจึงเป็นการประเมินความไม่แน่นอน
ภายใต้บันทึกเวลาที่มีอยู่ ไม่ใช่การอนุมานระดับประชากรเชิงเส้นกำกับ

## 13. เอกลักษณ์ที่ควรทราบก่อนอ่านผล

เมื่อช่วงเป้าหมายเป็นช่วงเดียวกับช่วงปรับแก้ อัตราส่วนการเปลี่ยนแปลง
เชิงสัมพัทธ์มีค่าเท่ากับหนึ่งตามนิยาม ทำให้ QDM ลดรูปเป็น EQM พอดี
ค่า `max|QDM − EQM|` ในช่วงปรับแก้จึงเท่ากับศูนย์ทุกแบบจำลอง

**นี่คือเอกลักษณ์ทางคณิตศาสตร์ ไม่ใช่ข้อผิดพลาดของโปรแกรม**
และเป็นการตรวจสอบความถูกต้องภายในของการดำเนินการ
